## What matches (no change needed)

- **Settings rule formats.** The Permissions page still shows `Bash(git push *)` and `PowerShell(Remove-Item *)` as its own examples. A `*` at the end with a space before it also matches the bare command. Ask rules also apply to one part of a compound command, such as `cd x && git push`, and they still prompt in auto mode. Common PowerShell aliases are turned into the cmdlet name before matching, and matching ignores upper and lower case. `Edit(/kb/approved/plan.md)` is anchored at the project folder and covers every built-in tool that edits files. `Read(.env)` and `Read(.env.*)` match at any depth. `Read(/.secrets/**)` is anchored at the project folder.
- **Limits of the settings.** `docs/limits.md` says the read block does not cover a script that opens the file itself, and that the sandbox is the block for every process. The Permissions page and Best practices say the same.
- **Auto mode numbers.** `docs/limits.md` says auto mode asks again after an action is blocked 3 times in a row or 20 times in total. The "Permission modes" page says the same.
- **Reviewer file.** `name`, `description` and `tools` are valid fields, and `tools: Read, Grep, Glob` is the documented format. Best practices still shows almost the same file as its example, with "Skip style".
- **Rules file.** A file in `.claude/rules/` with no `paths` loads at launch with the same priority as `.claude/CLAUDE.md`. `template/.claude/rules/chief-of-staff.md` has no frontmatter, so it loads in every session. This is what `template/CLAUDE.md` says.
- **Imports and size.** `@kb/status.md` and `@kb/todo.md` are the documented format. All instruction files are far under the 200 lines the docs advise.
- **Skill files.** `name`, `description` and `disable-model-invocation: true` are valid fields in both skills. The docs advise `disable-model-invocation: true` for workflows with side effects, which fits both. Both files are far under the 5,000 tokens that Claude Code keeps of a skill after it makes the chat shorter.
- **Approval wording.** The Fable 5.2 guide says to be specific about the actions that need approval, to write "ask for approval before ..." and not "never ...", and to name the steps that need no approval. The rules file does all three.
- **Background agents.** "Each costs my usage" and "full brief" match "Know what subagents cost" and "Set expectations for subagents". The rules file has no line that tells the agent to delegate by default.
- **Lessons limit.** The guide warns that cautions pile up in notes. The 20-line limit and the pruning in "Learn" handle this. The memory post says the same about the part that loads in every session: it has to stay small.
- **"What you can stop doing".** None of the seven old habits in that table is in `template/`: no words in capitals, no "think hard", no "keep going", no file layout in `CLAUDE.md`. The `/clear` line in `docs/limits.md` matches the first row.

## Proposals (three at most)

All three were approved on 2026-11-13. See `kb/approved/decisions.md`.

### 1. Keep `AGENTS.md` alive when the install adds a `CLAUDE.md`

- **Source:** Claude Code "Memory", part "AGENTS.md", the first table, and "Share one file with other coding tools". Needs Claude Code v2.1.277 or later.
- **Rule it changes:** `template/SETUP.md`, step 1 ("For the other four files: if the file does not exist here, copy it exactly").
- **Why:** The table says: with an `AGENTS.md` and no `CLAUDE.md`, Claude reads the `AGENTS.md`. With an `AGENTS.md` and a `CLAUDE.md`, Claude reads "your `CLAUDE.md` files only". So in a project that works with only an `AGENTS.md`, the install copies `CLAUDE.md` and the project's own rules stop loading, with no message. This is the opposite of "the prompt no longer replaces a project's own files". Not tested in a live session.
- **Possible wording:** in step 1, after the `CLAUDE.md` part: "If the project has an AGENTS.md and CLAUDE.md does not import it, add the line @AGENTS.md at the top of CLAUDE.md and tell me." The same sentence in step 7 of the update skill. One line in `docs/limits.md` and in the part of `docs/guide.md` about projects that already have files.
- **Cost:** `template/SETUP.md` has 398 words and the limit is 400, so about 20 words must be cut from another step. One line in `template/.claude/skills/chief-update/SKILL.md`. It is a change in `template/`, so the reviewer reads it.

### 2. Tell the owner about `denyInsteadOfPrompting` before an autopilot run

- **Source:** Claude Code changelog, version 2.1.319 (6 Nov 2026), and the Settings page, table "Exceptions to managed settings precedence". The details are from the "Settings reference" page, which is not in `kb/sources.md`.
- **Rule it changes:** `template/.claude/skills/chief-autopilot/SKILL.md`, "Before you start", step 4: the warning "A permission question from Claude Code stops the run until you answer. Auto mode asks the fewest questions." Also the autopilot line in `docs/limits.md` and the "Autopilot" section in `README.md`.
- **Why:** The biggest limit of autopilot is that one permission question stops the whole run. The new setting is made for this: with `"denyInsteadOfPrompting": true` under `permissions`, Claude Code refuses a call that would wait on a prompt, and the turn goes on. The docs show it together with `"defaultMode": "auto"`. Then a push, a merge or a delete in autopilot is refused by Claude Code itself, and no longer only by the skill's advice.
- **Three things the owner must know.** (a) "A repository can't set it for you": it works only in `~/.claude/settings.json` or in a file passed with `--settings`. So the template cannot ship it, and the agent must not set it. The owner sets it. (b) In `~/.claude/settings.json` it is on for every session on the computer until the owner removes it. A file passed with `--settings` limits it to one session. (c) It also removes the question tool (`AskUserQuestion`), so "Before you start" and "When I am back" must work with plain text questions in such a session. Not tested.
- **Possible wording:** "A permission question from Claude Code stops the run until you answer. Auto mode asks the fewest questions. To have Claude Code refuse such an action and go on, start the session with a settings file that has `"denyInsteadOfPrompting": true` under `permissions` (Claude Code v2.1.319 or later). I set this myself. You do not."
- **Cost:** one longer sentence in the skill, two lines in `docs/`, one in `README.md` (138 lines now, the limit is 140). It is a change in `template/`, so the reviewer reads it. It should be tried once in the real autopilot test that is already in `kb/todo.md`.

### 3. Start the reviewer without the chief-of-staff rules

- **Source:** Claude Code "Subagents", "Frontmatter reference" (field `omitClaudeMd`, needs v2.1.271 or later) and "What loads at startup".
- **Rule it changes:** `template/.claude/agents/reviewer.md`, the frontmatter.
- **Why:** The docs say a custom subagent starts with every `CLAUDE.md` level and the project rules. So the reviewer also gets `.claude/rules/chief-of-staff.md`, which starts with "You are my chief of staff" and tells it to ask decisions as cards, save to `kb/`, and use the reviewer before a merge. None of that is the reviewer's job, and it costs tokens on every review. The docs describe `omitClaudeMd: true` for exactly this: "subagents that take everything they need from the delegation prompt". The reviewer's own prompt already says it gets the diff and the plan and nothing else.
- **Possible wording:** one new frontmatter line: `omitClaudeMd: true`.
- **Cost:** one line in `template/`, one line in `docs/limits.md` (the reviewer then does not see the project's own `CLAUDE.md` rules either, so a project rule the reviewer must know goes into its brief). An older Claude Code ignores the unknown field with no error, so nothing breaks there. The update skill never replaces `reviewer.md`: it shows the difference and asks. Not tested.

## Smaller notes (no proposal)

- **Lessons hold only mistakes.** "The components of agent memory" reports a test on the CL-Bench benchmark: with the rule "record only failures", Opus 5 and Opus 4.7 lost much of the gain that memory gave them. The post advises to tell Claude what memory is for, not how to use it. `kb/lessons.md` is "lessons from mistakes", which is close to that rule. But the template also saves decisions, status and the plan, so its memory is not only failures. Whether a wider lessons line helps here is inferred, not tested. It is a good candidate for the next review.
- **Push rule limit (repeated from the first review).** The Permissions page now has its own table "What a Bash rule doesn't match", and `git -C . push origin main` is in it. `docs/limits.md` names this kind of limit for delete, not for push and merge. One more sentence would do it.
- **Read block and `grep -r`.** The Permissions page says a `Read` deny rule does not apply to "a command that reads files without naming them, such as `grep -r pattern .`". `docs/limits.md` names only the script case.
- **The read block is also a write block.** The page says a `Read` deny rule also blocks the Edit and Write tools on the same path, "including creating a new file there". So the agent cannot create or fill a `.env` with its file tools in a project that uses the prompt. `docs/limits.md` does not say this.
- **Evidence (repeated from the first review).** Best practices says to ask for "the command it ran and its output", and that for a session nobody watched this is the only evidence. The rules say "Run the proof" and not "show the output". This matters most for autopilot.
- **Autopilot and early stops.** The Fable 5.2 guide says the model sometimes ends a long task early by listing what is left. Best practices names `/goal` and a `Stop` hook for runs nobody watches. The autopilot skill covers "do not ask me", not an early stop. Best practices also asks for a limit on turns or spend before a run with nobody there. Autopilot has none, and `docs/limits.md` says only that the run ends at the usage limit.
- **`disallowed-tools` in a skill.** The Skills page describes it "for autonomous skills that should never call certain tools, such as `AskUserQuestion`". It clears at the owner's next message, which fits "the mode ends when I write to you again". It does not fit as it is, because "Before you start" may ask.
- **Git instructions.** The Memory page says a `CLAUDE.md` with its own commit or pull request rules competes with the ones Claude Code adds, and names the setting `includeGitInstructions`. The rules file has branch and merge rules. No problem was seen.
- **Rules after `/compact`.** The Memory page says the project-root `CLAUDE.md` is read again from disk after compaction. It does not say this for a rules file with no `paths`. Not tested.
- **Harness post.** It supports two things the template already does: a reviewer separate from the writer, and removing parts of a harness one at a time to see which ones still matter.
- **Page the owner may want to add to `kb/sources.md`:** Claude Code "Settings reference" (`https://code.claude.com/docs/en/settings-reference`) and "Permission modes" (`https://code.claude.com/docs/en/permission-modes`). Proposal 2 and the auto mode line in `docs/limits.md` rest on them.
- **File name.** This is the second review on the same date, so the file has `-2` at the end of its name. The first report was not changed.
