## What matches (no change needed)

- **Settings rule formats.** `Bash(git push *)` with a space before `*` also matches the bare command. `PowerShell(Remove-Item *)` is the docs' own example. The docs say common aliases are turned into the cmdlet name first (their example is `Get-ChildItem` for `gci`, `ls`, `dir`), so `rm` and `del` in PowerShell should match too. This is not tested here. `Edit(/kb/approved/plan.md)` is anchored at the project folder and covers every tool that edits files, so no `Write(...)` rule is needed. `Read(.env)` matches a `.env` at any depth. Ask rules still prompt in auto mode.
- **Limits in README.** "It does not cover a script that opens the file itself" and "turn on the Claude Code sandbox" say the same as the Permissions page.
- **Reviewer.** `tools: Read, Grep, Glob` plus "skip style" is almost the same file as the example in Best practices.
- **Imports.** `@kb/status.md` and `@kb/todo.md` at the end of `CLAUDE.md` are the documented format. The 100-line limit in the check script is under the 200 lines the docs advise.
- **Approval wording.** The Fable 5.2 guide says to write "ask for approval before deleting files" and not "never delete files", and to name the steps that need no approval. The template does both.
- **Lessons limit.** The guide warns that cautions pile up in notes. The 20-line limit and the pruning in "Learn" already handle this.
- **Background agents.** "Each costs my usage" and "full brief" match "Know what subagents cost" and "Set expectations for subagents".

## Proposals (three at most)

### 1. Make "send" exact in the approval rule

- **Source:** "Prompting Claude Fable 5.2", part "Approvals".
- **Rule it changes:** `template/CLAUDE.md`, Approval: "Settings cannot catch send, publish, deploy, or pay. Ask me first for those too, because they cannot be undone."
- **Why:** The guide says to be specific about the actions that need approval. In Anthropic's tests, a wide rule about sending messages made the model hold back about half of its routine requests. "Send" alone can be read to include a brief to a background agent or a normal reply.
- **Possible wording:** "Settings cannot catch these: sending email or messages to other people, publishing, deploying, and paying. Ask me first for those too, because they cannot be undone."
- **Cost:** one line in `template/`, one matching line in "What it does, and what it does not".

### 2. Update the README line about a full memory

- **Source:** Claude Code "Best practices", part "What you can stop doing" and "Keep cost and context down".
- **Rule it changes:** `README.md`: "The agent cannot see how full its memory is. Check `/context` yourself, and start a new session (after the agent has saved) before it gets very full."
- **Why:** The docs now call "manage the context window aggressively" old advice. Most current models have a 1M-token window and compact by themselves. The reason to start fresh is now focus and cost, not running out.
- **Possible wording:** "Long chats cost more and lose focus. Type `/clear` between tasks (after the agent has saved). You rarely run out of memory now, because Claude Code makes the chat shorter by itself."
- **Cost:** README only. No change in `template/`.

### 3. Add `/doctor prompt-audit` to the review

- **Source:** Claude Code "Memory", part "Audit your instruction files" (needs Claude Code v2.1.283 or later).
- **Rule it changes:** the review rules at the top of `kb/sources.md`.
- **Why:** This command checks `CLAUDE.md`, agents, and skills for instructions written for older models, for files that do not exist, and for rules that contradict each other. It changes nothing until asked. This is the same goal as the sources review, done by a built-in tool. Only the owner can type it.
- **Possible wording:** "At each review, the owner runs `/doctor prompt-audit template` and the agent adds the findings to the research file."
- **Cost:** one line in `kb/sources.md`. No change in `template/`.

## Smaller notes (no proposal)

- **Import paths in this repo only.** The docs say a relative import resolves from the file that holds it. So when the root `CLAUDE.md` imports `template/CLAUDE.md`, the two `@kb/...` lines inside the template point to `template/kb/`, which does not exist. Nothing breaks, because the root `CLAUDE.md` has its own two import lines. Projects that use the prompt are not affected.
- **Push rule has the same kind of limit as the delete rule.** `Bash(git push *)` does not stop `git -C . push`. README names this limit for delete, not for push. It could be one more sentence.
- **Evidence.** Best practices says to ask for the command and its output, not only "all tests pass". The template says "Run the proof" and does not say "show the output".
- **`/code-review`.** Claude Code now has a built-in review in a fresh subagent. The template's own reviewer does the same job and checks against the plan, so it stays.
- **New on the engineering blog, not read yet:** "The components of agent memory" and "Harness design for long-running application development". Both are close to this prompt's topic and are good first reads for the next review.
