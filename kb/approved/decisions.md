# Decisions

- 2026-11-13: Ship the rules as files in `template/`; the prompt copies them. Reason: the same rules in every project, and a script can check them.
- 2026-11-13: Check the files with a script and no model (`scripts/check.py`), run by GitHub Actions. Reason: testing must cost nothing.
- 2026-11-13: No paid test runs on fake projects, and no smoke run per model release. Reason: cost.
- 2026-11-13: No manual live-session check of the settings rules for now. Reason: owner's choice.
- 2026-11-13: Feedback on the prompt comes from the owner's own projects, in `kb/chief-prompt-lessons.md`. It is for the owner only and is not in the template. Reason: real use is better evidence than fake projects, and other users do not need it.
- 2026-11-13: `kb/chief-prompt-lessons.md` is a separate file from `kb/lessons.md`. Reason: `lessons.md` has a 20-line limit and gets pruned.
- 2026-11-13: This repo uses its own prompt. Reason: the owner's first real project for feedback.
- 2026-11-13: Keep the repo up to date by reading the pages in `kb/sources.md` at each "Learn" review (option B). No scheduled agent for now. Reason: no new machinery, and the prompt has no real-project use yet, so automation is early.
- 2026-11-13: Approved all three proposals from `kb/research/sources-2026-11-13.md`. (1) The approval rule in `template/CLAUDE.md` says "sending email or messages to other people", not "send". Reason: a wide "send" rule makes the model hold back routine work. (2) The README line on a full memory now gives cost and focus as the reason for `/clear`. Reason: the docs call the old reason out of date. (3) The owner runs `/doctor prompt-audit template` at each sources review. Reason: a built-in check for old or conflicting rules.
- 2026-11-13: Widen the new approval wording to "sending email, messages, files or data to other people or outside services". Reason: the reviewer found that the narrow wording no longer covered an upload or a POST to an outside service, which cannot be undone.
- 2026-11-13: Make the sources review a skill now (`.claude/skills/sources-review/`), in this repo only, and no extra agent. Reason: the task repeats by design, the steps from the first run are fresh, and an agent would add cost with no gain we can measure. This is earlier than the "repeats twice" rule in the template.
- 2026-11-13: One approval covers the whole ship step: push, PR, merge, and delete of the merged branch. The rule goes into `template/CLAUDE.md`, so every project gets it. Reason: three questions for each change was too many, and the cause was the template. The ask rules in `.claude/settings.json` stay as they are. After the reviewer's findings, the rule also says: the question comes only after the proof and the review, push and PR apply only with GitHub, and branches from parallel writers stay with the owner.
- 2026-11-13: No meeting of several Claude models (Haiku, Sonnet, Opus, Fable) on each update, and no weak-model read test or outside-model view for now. The `reviewer` agent stays the only second opinion. Reason: models from one family mostly agree, the same task given to more agents does not give a better answer, and each run costs usage.
- 2026-11-13: Split the template into "ours" and "yours" (option A). The chief-of-staff rules move to `.claude/rules/chief-of-staff.md`, which the prompt owns and an update replaces. `CLAUDE.md`, `.gitignore`, `.claude/settings.json` and `.claude/agents/reviewer.md` belong to the project: the agent copies one only if it is missing, and else adds only the missing lines. Reason: the old prompt stopped in almost every existing project, and its only clean choices were to overwrite the owner's files or to skip them. An update by copy also deleted the Language line and the project's own rules.
- 2026-11-13: Add an update skill to the template (`.claude/skills/chief-update/SKILL.md`), as a second file the prompt owns. The user types `/chief-update` in a project. Reason: an update repeats in every project after each template change, and it merges settings, so the exact steps matter. Only the user can start it, because it changes files.
- 2026-11-13: One-line install (option A). The five steps move to a file in `template/`, and `README.md` shows one line that tells the agent to clone the repo and follow that file. Reason: one line is easier to paste, and the steps can change without a new paste. The update is already one line, `/chief-update`.
- 2026-11-13: Add `CHANGELOG.md` and a "Last updated" line at the top of `README.md` with the date and the model (option A). The check script fails if the line is missing or its date is not the newest date in the changelog. Reason: a reader sees at once how old the prompt is and which model wrote the last change.
- 2026-11-13: Autopilot is a mode the user turns on, never the default (option B, "long leash"). The agent works alone inside the repo only. It stays private: local only, or a push to a private repo or branch. When it does not know what to do, it may wait, or go ahead and build the options, and the owner decides later which ones to delete. Details are still open and start as a draft in `kb/research/`. Reason: the owner wants work to continue while away, but sending, publishing and paying cannot be undone.
- 2026-11-13: Autopilot works local only, on one `autopilot` branch, with no push (4.1, option A). Reason: nothing can leak, and the settings stay as they are.
- 2026-11-13: At an open question, autopilot takes its own pick, continues on that line, and writes the question to a file. It builds the other options only when they are small, each on its own branch, and never options on top of options (4.2, option A). When the owner is back, the agent asks one card per question, and the owner says which branches to delete. Reason: building every option costs three times the usage, and the number of branches grows too fast.
- 2026-11-13: Autopilot has no task limit. It runs until `kb/todo.md` is empty (4.3, option B). Reason: owner's choice. The agent proposed three stops (a task limit, two failed checks, a question about the outside world); the owner did not take them.
- 2026-11-13: Approved all six open points in `kb/research/autopilot.md`. (1) A failed check: fix twice, then `git revert` the task, mark it blocked, go to the next task. (2) One `autopilot` branch, no merge, no file delete; option branches stay apart. (3) A task that depends on a blocked task is skipped and listed. (4) One commit per task. (5) Runs over many days are not in the first version. (6) The mode is a skill, `/chief-autopilot`. Reason: with no task limit, failed work must not stay on the branch, and the ask rules in the settings would stop a run that merges or deletes.
- 2026-11-13: The GIF idea changes. `README.md` gets several pictures (GIFs, illustrations or diagrams), not one GIF. It also gets shorter if possible: the main ideas and the important things at the top, the long parts at the bottom. Reason: the owner finds the file hard to understand and boring. Which pictures and which layout are still open.
- 2026-11-13: The pictures are Mermaid diagrams written as text inside `README.md` (R1, option A). GIFs of a real session come later, after a real run. Reason: no image files, GitHub draws them in light and dark, and they are easy to change.
- 2026-11-13: Three diagrams: the setup flow, how one task goes, and who decides (R2, option A). Reason: these are the three main ideas of the prompt.
- 2026-11-13: Split the README (R3, option A). `README.md` stays short, and the long parts move to `docs/`: the guide, all limits, "Why one agent", and the maintainer part. The five most important limits stay in `README.md`. Reason: the important things must be on the first screen.
- 2026-11-13: The first promise in `README.md` now says "It asks you before it sends, publishes, deploys, pays, deletes, or merges", not "It never ... without your approval". Reason: the reviewer found the old line false. Sending, publishing, deploying and paying are advice only, and the agent may delete files it created on its own branch. The owner had said to ship once the reviewer finds no blocking problem, so the agent made this fix; the owner can change the wording.
- 2026-11-13: Build the autopilot skill now (`template/.claude/skills/chief-autopilot/SKILL.md`), as the third file the prompt owns. Reason: owner's yes. Two things differ from the approved draft, both chosen by the agent, and the owner can reject them. (1) Failed work goes into a named `git stash`, not `git revert`, and work gets a commit only after the proof passes. Reason: a revert needs a commit of failed work first, and removing new files needs `rm`, which the settings ask about. A stash removes the work from the branch and keeps it for the owner. (2) The skill names auto mode as the mode with the fewest questions. Reason: the permission modes page of the Claude Code docs (read 2026-11-13) says ask rules prompt in every mode, and that only containers should use the mode that skips all checks.
- 2026-11-13: The owner said yes to `git stash` for failed work in autopilot, in place of `git revert`. Reason: a stash needs no commit of failed work and no `rm`, and it keeps the work for the owner.
- 2026-11-13: `README.md` may have 140 lines and 4 diagrams (autopilot question 1, option a). The limit in `scripts/check.py` and the rule in root `CLAUDE.md` say so. Reason: the owner wants autopilot to have its own section with a diagram in the README, and no other part should move out for it.
- 2026-11-13: The update has its own line to paste in `README.md`, and `/chief-update` stays as the second way (autopilot question 2, option a). Reason: the update should be as simple as the install. The line reads the newest update steps from the clone, so one run is enough and a project needs no update skill.
- 2026-11-13: Sources review 2, proposal 1, yes (option A). The install adds `@AGENTS.md` as the first line of a new `CLAUDE.md` when the project has an `AGENTS.md`, and asks first when `CLAUDE.md` already existed. The update skill asks too. Reason: the Memory page says Claude Code reads only `CLAUDE.md` when both files exist, so the install would switch off the project's own `AGENTS.md` rules. The ask for an existing `CLAUDE.md` is the agent's choice: the owner of such a project may have left the import out on purpose.
- 2026-11-13: Sources review 2, proposal 2, yes (option A). The autopilot warning names the setting `permissions.denyInsteadOfPrompting` (Claude Code v2.1.319 or later). Only the owner sets it. Reason: one permission question stops a whole autopilot run, and with this setting Claude Code refuses the action and the run goes on. A repository cannot set it, so the template does not ship it.
- 2026-11-13: Sources review 2, proposal 3, yes. `reviewer.md` gets `omitClaudeMd: true`. Reason: the reviewer takes everything from its brief (the diff and the plan), and the chief-of-staff rules are not its job.
